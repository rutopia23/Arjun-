# API reference

Every HTTP and WebSocket endpoint of **core-api** (:8000) and **reasoning** (:8001), grouped by purpose, with who
calls it and how it is authorised. Exact request/response schemas are generated by FastAPI: with the stack
running, open **http://127.0.0.1:8000/docs** and **http://127.0.0.1:8001/docs** (OpenAPI / Swagger). This file
explains *what each route is for and the rules around it*, which the generated docs do not.

Contents: [Conventions](#conventions) · [Authentication](#authentication) · [core-api](#core-api) ·
[reasoning](#reasoning) · [voice-agent helper](#voice-agent-helper-endpoint) · [Web dev proxy](#web-dev-proxy-and-vercel-functions) ·
[Examples](#examples)

## Conventions

* JSON in, JSON out. Errors are FastAPI-style `{"detail": ...}` with 401 (bad key), 403 (cross-site), 404
  (unknown user/item or an item that belongs to another user), 409, 422 (validation: missing slot, bad time),
  429 (rate limited, with `Retry-After`) or 503 (`CORE_API_KEY` not configured).
* `{user_id}` is the **elder's** id (`users.id`), never an account id.
* Times are naive household-local ISO strings (`2026-11-16T10:00:00`); dates `YYYY-MM-DD`; clock times `HH:MM`.
* Anything under `/internal/*` is for other services (scheduler, voice-agent). It uses the same key.
* Medicine name/dose are always returned **exactly as entered**.
* Nothing returns transcripts: wellbeing, distress and activity routes carry levels, moods, short
  paraphrases and timestamps only.

## Authentication

| Mode | Used by | How |
|---|---|---|
| **Service key** | scheduler, reasoning, voice-agent, the web dev proxy | header `X-API-Key: <CORE_API_KEY>` (constant-time compare). core-api refuses to start without it |
| **Family session** | browser, when `ARJUN_AUTH=1` | `arjun_session` HttpOnly cookie from `/auth/login`/`/auth/signup`; the request must be allowed for that elder via `memberships` |
| **Elder device** | paired elder device, when `ARJUN_AUTH=1` | `arjun_device` cookie from `/devices/pair` |
| **Signed link** | Telegram "join call" | short-lived signed token in `GET /family/join` |
| **Self-authenticated** | `WebSocket /ws/users/{id}/feed`, `POST /livekit/token` | checked inside the handler (`authorize_websocket`, `require_livekit_access`) |
| **Open** | `GET /health` | health probe |

`require_key` order: a valid service key always passes; otherwise, if `ARJUN_AUTH=1`, a valid session/device
cookie authorised for that elder passes; otherwise 401 (503 if no key is configured). `ARJUN_TESTING=1` (tests
only) lets requests through without a key. Unsafe browser requests that carry a cookie and an `Origin` other than
`BASE_URL`/localhost get 403 (`origin_guard.py`).

## core-api

### Health and diagnostics
| Method & path | Purpose |
|---|---|
| `GET /health` | liveness (no auth, exempt from rate limit) |
| `GET /diag/base-url` | is `BASE_URL` usable for family links? (ok / unreachable / quick-tunnel) |
| `GET /metrics/voice` | numeric-only summary of voice turn timings read from `turns.jsonl` (never transcripts/replies) |

### Users and contacts
| Method & path | Purpose |
|---|---|
| `POST /users` | create an elder (demo/seed; with accounts use `POST /parents`) |
| `GET /users/{id}` | profile: name, language, meal times, consent, speech style, `address_as`... |
| `PATCH /users/{id}` | update profile (family edits). Existing **names cannot be changed** through this endpoint |
| `POST/GET /users/{id}/contacts` | add / list family contacts and doctors |
| `PATCH/DELETE /users/{id}/contacts/{cid}` | edit / remove |

### Reminders, appointments, the day
| Method & path | Purpose |
|---|---|
| `POST /users/{id}/reminders` | create (past times and ambiguous input are rejected, 422) |
| `GET /users/{id}/reminders` · `GET .../reminders/today` | list / today's |
| `POST .../reminders/{rid}/complete` · `DELETE .../reminders/{rid}` | mark done / delete |
| `POST/GET /users/{id}/appointments` · `GET .../appointments/next` | one-off or weekly (`weekdays`, `start_time`, `end_time`) |
| `GET /users/{id}/day?on=YYYY-MM-DD` | one SQL-backed view of a day: reminders, appointments, medicines with status. A future day is read-only and computed from the family schedule; nothing is written |
| `GET /users/{id}/activity` · `POST .../activity` | last time she spoke / tapped (time only) |

### The propose → confirm / undo ledger (the LLM-never-touches-the-DB boundary)
| Method & path | Purpose |
|---|---|
| `POST /users/{id}/actions/propose` | `{action_type, payload}`; validated server-side (`_validate_payload`); supersedes older unconfirmed proposals. Types: `CREATE_REMINDER`, `COMPLETE_REMINDER`, `REQUEST_CAREGIVER`, `SHARE_STORY`, `SAVE_STORY`, `MEDICINE_TAKEN`, `MEDICINE_SNOOZE`. 422 on missing/invalid slots |
| `GET .../actions/pending` | the open proposal, if any (expires after `PENDING_TTL_S`, 300 s) |
| `POST .../actions/{aid}/confirm` | execute it |
| `POST .../actions/{aid}/undo` | undo within `UNDO_TTL_S` (180 s). A help request cannot be unsent: a second note goes to the family |
| `POST .../actions/{aid}/reject` | cancel |

### Help, distress, wellbeing
| Method & path | Purpose |
|---|---|
| `POST /users/{id}/issue` | "she is facing an issue" → urgent family notification |
| `POST /users/{id}/distress` | `kind: distress|emergency`. **Emergency always alerts**; distress only if `consent_distress_alert`. Stores no transcript |
| `POST /users/{id}/lonely` · `POST .../health-complaint` | consent-gated "watch" notes for the family |
| `POST /users/{id}/alert/test` | send a test Telegram alert |
| `GET /users/{id}/caregiver-requests` · `GET .../notifications` | what the family has been told |
| `POST /users/{id}/declines` · `GET .../opener-allowed` | "नको" to an opener; the gate that blocks more that day |
| `POST/GET /users/{id}/wellbeing` · `GET .../wellbeing/today` | per-conversation severity / mood / paraphrase; one-glance "how is she today" |
| `GET /users/{id}/feed?after=` · `WS /ws/users/{id}/feed` | the family live feed (push + polling fallback) |
| `POST/GET /users/{id}/sound-events` · `POST .../sound-events/escalate` | optional sound labels (off by default) |

### Stories and facts
| Method & path | Purpose |
|---|---|
| `POST /users/{id}/stories` · `GET .../stories/latest` · `DELETE .../stories/{sid}` | private stories; "he visar" deletes |
| `GET /users/{id}/memory-book` | **shared** stories only |
| `GET /users/{id}/stories/search` | light retrieval over her own stories (`rag.py`) |
| `POST/GET /users/{id}/facts` · `DELETE .../facts/{fid}` · `POST .../facts/forget` · `POST .../facts/{fid}/used` | long-term facts (refuses numbers, addresses, medicines...). `forget` implements "विसरून जा" |

### Medicines (family-only writes)

|---|---|

| `GET .../medicine-doses` · `GET .../medicines/due` | today's doses / what is due now |
| `POST .../medicine-doses/{did}/taken` · `.../snooze` | self-reported taken / snooze |
| `POST /internal/medicines/tick` | scheduler: create doses, remind, mark `unconfirmed` and tell only the family |
| `GET/PUT /users/{id}/health-profile` · `GET .../medicine-check` | family health notes; the day's medicine check |

### Delivery queue (T8)
| Method & path | Purpose |
|---|---|
| `POST /internal/reminders/fire-due` | scheduler: due reminders → `fired` + notification + enqueue |
| `POST /internal/deliveries/sweep` | retire finished, apply late/backlog rules, notify undelivered |
| `GET /users/{id}/deliveries/next` · `/waiting` · `/open` · `/{did}` · list | what a voice session should speak / what is outstanding |
| `POST .../deliveries/{did}/claim` | atomically claim (`{session}`) |
| `POST .../deliveries/{did}/spoken` | mark spoken **after playback finished** |
| `POST .../deliveries/{did}/release` | give it back (`reason: tts|interrupted`) |
| `POST .../deliveries/{did}/ack` | the elder answered / acknowledged |

### Check-ins (family opt-in)
`GET /internal/checkin-users`, `POST /internal/checkins/tick`, `GET .../checkins`, `GET .../checkins/open`,

### Emergency
| Method & path | Purpose |
|---|---|

### Apps, media, calls, briefings, voices
| Method & path | Purpose |
|---|---|
| `GET/POST /users/{id}/app-links` (alias `/apps`) · `PATCH/DELETE .../{aid}` · `GET .../apps/match` | family-approved YouTube / RSS / WhatsApp / links |
| `GET /media/youtube/search` · `GET /media/status` · `GET /media/news` · `GET /users/{id}/news` | YouTube search (key stays here, 24 h cache, daily cap), headlines from the family's feeds |

| `GET /family/join` · `POST /family/calls/answer` · `POST /family/calls/end` | family joins the elder's LiveKit room |

### Accounts and devices (`ARJUN_AUTH=1`)
| Method & path | Purpose |
|---|---|
| `POST /auth/signup` · `/auth/login` · `/auth/logout` · `GET /auth/me` | family account (email + password ≥ 10 chars; sign-up needs `ARJUN_SIGNUP_CODE` unless open signup is allowed) |
| `GET/POST /parents` · `GET/PATCH/DELETE /parents/{pid}` | the elders this account can see |
| `POST /parents/{pid}/invite` · `POST /auth/accept-invite` | add another family member |

### Health readings (frozen feature)
`POST/GET /users/{id}/bp-readings`, `POST/GET /users/{id}/watch-samples`, `GET .../watch-samples/latest`.
Raw numbers only; no judgement is stored or returned.

## reasoning

Auth: reasoning is an internal service; in compose and local runs it is reachable only from the other services
and the dev proxy. It calls core-api with the service key.

| Method & path | Purpose |
|---|---|
| `GET /health` | `{status, llm_configured, llm_provider, llm_model, ask_before_acting}` (never the key) |
| `POST /turn` | **the main call.** Body `{user_id, text (1–2000), language_code?, reply_language?}` → `TurnOut` |
| `WS /turn/stream` | streaming twin of `/turn` (frames below). If `ARJUN_INTERNAL_KEY` is set, the socket must send it in the `x-arjun-internal` header; unset = open, like `/turn` (internal port) |
| `POST /turn/prepare` | rules-only, millisecond pre-step (filler, language); touches no state |
| `POST /media/gate` | `{user_id, text}` → `{safety, control}` for media mode; rules only, works when everything else is down |
| `POST /media/stopped` · `POST /media/call-stopped` | clear media-mode / video-call state |
| `POST /delivery/next` · `POST /delivery/{id}/spoken` · `POST /delivery/{id}/release` · `GET /session/{user_id}/busy` | voice session pulls and reports queued reminders/medicines |
| `POST /sound-event` · `POST /sound-event/escalate` | optional sound-event path |
| `POST /conversations/flush-idle` | scheduler: summarise conversations quiet for `CONVERSATION_IDLE_S` |
| `GET /briefing/{user_id}` · `POST /opener/{user_id}` | day briefing text; one interest opener (null = do not open) |

### `TurnOut`
| Field | Meaning |
|---|---|
| `reply` | the text shown on screen (no voice tags) |
| `speech` | what the voice says (may carry one Timbre v3.0 tag); empty = say `reply` |
| `intent` | e.g. `CREATE_REMINDER`, `SHOW_DAY`, `MEDICINE_TAKEN`, `CHAT`, `UNKNOWN`, `EMERGENCY`... |
| `mode` | `care` (fixed templates), `companion` (LLM chat) or `safety` |
| `language` | language of the reply (`mr hi en bn gu kn ml pa ta te`) |
| `awaiting_confirmation` | true only in `ARJUN_ASK_BEFORE_ACTING=1` mode |
| `screen` | which elder screen to show: reply / story / confirm / saved / safety (safety wins) |
| `action` | `{type: open|control|choice|none, kind, value, title, choices?}`: what the elder page should open or do, chosen from the family's `app_links`, never by the LLM |
| `source` | `rules` or `llm` |
| `trace` | route, reason for fallback, timings (no words) |
| `speech_style` | `{rate, volume, simple, companion_name}` |
| `silent` | true = say nothing (noise, system marker) |
| `filler` | "बघतो…" for a live lookup |
| `active_language` | a spoken language switch in force, else "" |

`/turn` returns 429 only for non-safety text over `TURN_RATE_PER_S`/`TURN_RATE_BURST` (default 2/s, burst 6);
**emergency and distress text is never rate limited**. A core-api failure maps to 502 (or its own 4xx).

### `/turn/stream` frames (JSON text)
Client → server: `{"type":"turn","user":7,"text":"...","lang":"mr-IN","turn_id":"t1","reply_language":"hi"}`
and `{"type":"cancel","turn_id":"t1"}` (barge-in).
Server → client, in order: `ack` (rules only, immediate) → `sentence` ×N (one per complete, **guarded** sentence)
→ `final` (the full `TurnOut`) → optional `action`; or `error` / `cancelled`. Turns of one user are served in
arrival order. No unguarded token is ever emitted.

## voice-agent helper endpoint

The worker also hosts a tiny uvicorn app on **127.0.0.1:8002** (`briefing_audio.py`): `POST /synthesize` turns
briefing text into OGG/Opus so core-api can send a Marathi voice note over Telegram while the Gnani key stays
inside the voice-agent process. Loopback only; configured by `BRIEFING_VOICE_URL`. (The worker's LiveKit health
server listens on a separate random port, e.g. `:61751`.)

## Web dev proxy and Vercel functions

The browser only ever calls **`/core/*`**:

* **Local** (`web/vite.config.ts`): Vite proxies `/core/*` → `CORE_API_URL` (default `http://127.0.0.1:8000`), strips
  the prefix, injects `X-API-Key`, and upgrades WebSockets. `web/server/access.ts` decides whether to inject the key:
  always for this laptop; through a tunnel only with a valid role-limited `arjun_access` cookie
  (`ARJUN_ACCESS_CODE`). Family **account** routes (`/auth/*`, `/parents*`) go through with the browser's own
  `arjun_session` cookie and **no key**.
* **Cloud** (`web/vercel.json`, `web/api/core.ts`, `entry.ts`, `_gate.ts`): the same role is played by Vercel
  serverless functions (`/core/:path*` → `/api/core`). Unverified: see [DEPLOY_CLOUD.md](DEPLOY_CLOUD.md).

## Examples

```bash
KEY=$(grep '^CORE_API_KEY=' .env | cut -d= -f2)

# What is on today's list?
curl -s -H "X-API-Key: $KEY" http://127.0.0.1:8000/users/1/day | jq

# Ask reasoning something, as if the elder said it (no voice needed)
curl -s -X POST http://127.0.0.1:8001/turn -H 'Content-Type: application/json' \
  -d '{"user_id":1,"text":"उद्या सकाळी दहा वाजता डॉक्टरकडे जायचं आहे"}' | jq '{reply,intent,mode,source}'

# What reminders now exist?
curl -s -H "X-API-Key: $KEY" http://127.0.0.1:8000/users/1/reminders | jq

# Undo the last action (id from /actions/pending or the turn trace)
curl -s -X POST -H "X-API-Key: $KEY" http://127.0.0.1:8000/users/1/actions/12/undo
```
PowerShell users: use `Invoke-RestMethod -Headers @{ "X-API-Key" = $key } ...`. Use synthetic data only.

`scripts/converse_test.py` runs scripted multi-turn dialogues in process (reasoning plus an in-memory core-api, synthetic user) and prints what reached the LLM, and `scripts/make_token.py` mints
a LiveKit token with the `arjun` dispatch for Console-style tests.
